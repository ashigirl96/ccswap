usage: {prog} auto [-h] [--once] [--json] [--interval SECONDS]
                   [--threshold PCT] [--cooldown SECONDS] [--model NAMES]
                   [--include-api-key-accounts | --no-include-api-key-accounts]
                   [--strategy {best,consume-first}] [--dry-run] [--debug]

Automatically switch accounts when the active one nears its 5h/7d rate limit. Runs a foreground polling loop; use --once for a single tick (cron-friendly).

options:
  -h, --help            show this help message and exit
  --once                Evaluate once, maybe switch, and exit (exit code =
                        outcome)
  --json                Emit one machine-readable JSON event per line on
                        stdout
  --interval SECONDS    Poll interval in loop mode (min 15; default 60)
  --threshold PCT       Switch when the active account's binding 5h/7d window
                        reaches this utilization (50-99.9; default 90)
  --cooldown SECONDS    Minimum time between proactive switches (default 300)
  --model NAMES         Also switch when a per-model weekly limit is hit, not
                        just the account-wide 5h/7d windows. One name or a
                        comma-separated list (e.g. Fable, Opus, Sonnet, Haiku,
                        or 'Fable,Opus'), or 'all' for every per-model window
                        an account reports
  --include-api-key-accounts, --no-include-api-key-accounts
                        Allow switching onto managed API-key accounts as a
                        last resort (they bill per token; default: excluded)
  --strategy {best,consume-first}
                        Target selection: 'best' (most quota left; default) or
                        'consume-first' (proactively use the account whose
                        weekly window resets soonest)
  --dry-run             Evaluate and report, but never switch or write state
  --debug               Enable debug logging

Exit codes with --once:
  0  switched to another account
  1  error (network trouble, lock contention, ...)
  2  no action needed
  3  blocked: wanted to switch but no viable target / all exhausted

Examples:
  {prog} auto                       # foreground loop, switch at 90%% used
  {prog} auto --threshold 80        # switch earlier
  {prog} auto --model Fable         # also switch when the Fable weekly limit is hit
  {prog} auto --json                # one JSON event per line (for scripts)
  {prog} auto --once; echo $?       # single tick, outcome in exit code
  {prog} auto --dry-run             # log decisions, never actually switch

Defaults live in settings.json in the backup root; flags override them.
